# C2.3.3 discovery browser architecture reassessment

Status: 304 correction implemented; C2.3.3/C-B04 blocked. This decision does not qualify human authentication.

| Required boundary                                        | Native Playwright support                                                                                                                             | Remaining Appraise responsibility                                                                                                                 |
| -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fresh interactive authentication and process-local state | Browser contexts, cookies and browser-managed login support this. `storageState` can serialize secrets, so the product does not export or restore it. | Bind one context to the frozen Journey, target, environment and work item; expire, revoke, replace and close it.                                  |
| Initial HTTP request and popup request policy            | `browserContext.route` can intercept initial requests, including a popup's first request when installed before pages.                                 | Authorize each request against the frozen origin/path/method/kind policy before contact.                                                          |
| Every redirect successor                                 | The retained Playwright fetch/fulfill Chromium test demonstrated that a redirect follow-up can bypass its route before revocation.                    | Keep response-stage redirect checks and request-stage successor admission until a smaller implementation proves the same zero-contact invariant.  |
| New targets and workers                                  | Page/popup events alone are too late for pre-execution target admission. An allowed worker script may be fetched before its target exists.            | Retain recursive paused-target admission; claim worker execution containment only.                                                                |
| WebSockets and service workers                           | Playwright offers context WebSocket routing and `serviceWorkers: 'block'`.                                                                            | Keep the qualified pre-document deny-only socket control and worker target gate; a later event is a terminal signal, not pre-contact enforcement. |
| Return, evidence and lifecycle                           | Browser state can show a navigation, but cannot grant Appraise authority.                                                                             | Require the exact one-shot human return, committed main frame, local confirmation, sealed receipt and Scout admission; keep gates distinct.       |

The smallest currently qualified implementation retains the canonical Appraise service and the production CDP gate for every-hop and paused-target controls. It uses Chromium's native request, cookie, redirect, cache and page behavior rather than replaying login requests in application code. The custom process/pipe transport is substantial; replacing it with a Playwright-managed browser and browser-level CDP session would still require CDP and fresh containment qualification. It is outside this bounded repair.

The synthetic status isolation proved that the adapter incorrectly classified HTTP 304 without Location as a redirect. It did not establish the live Auth0 status. This repair excludes 304 from redirect tracking in the adapter and service, including exact human return, while retaining fail-closed behavior for true redirects. Qualification-only probes, reviewed fixed-shape UI projection, and frozen hosted fixtures remain separate from product authority and are not removed or promoted.

Independent architecture review recommended retaining the production gate and required regressions for initial-request-only policy, exact return, real Chromium 304 handling and true redirects. The new Chromium case uses an explicit `If-None-Match` request to obtain a real 304 response pause; automatic browser cache revalidation and cached-body reuse were not established. The existing denied redirect successor case still proves zero contact with its forbidden destination.

Validation: 137 focused service/runtime tests and 83 headed/headless production adapter tests passed; affected-file ESLint, Prettier, TypeScript, root-to-template byte parity, `prepare-template`, Graphify auto-update and production build passed. The first production build attempt could not fetch configured Google Fonts inside the sandbox; the permitted host retry passed. Final exact-artifact review and a fresh credential-free Auth0 sign-up check remain separate evidence steps.
