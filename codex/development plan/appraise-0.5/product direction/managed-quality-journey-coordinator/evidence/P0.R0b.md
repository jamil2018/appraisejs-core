# P0.R0b — Isolate no-model qualification launch

Status: `verified`

## Scope

This task isolates the account-free App Server qualification launch. It must not call `turn/start`, copy normal
Codex account state, inherit the broad parent environment or claim that synthetic evidence qualifies a real provider
manifest.

## Implementation slices

- P0.R0b.a — pure launch composition and allowlisted environment
- P0.R0b.b — deterministic synthetic MCP modes
- P0.R0b.c — owned process identity and verified cleanup
- P0.R0b.d — sanitized resolved-config/inventory receipt integration

## Implemented artifact

- `scripts/lib/managed-journey-isolated-launch.mjs` composes a disposable `CODEX_HOME`, separate working directory,
  explicit synthetic MCP configuration, allowlisted child environment and content-bound launch digest. Its sanitized
  receipts hash configuration source paths and raw resolved configuration rather than recording their contents.
- `packages/appraisejs/scripts/managed-journey-synthetic-mcp.mjs` is an account-free stdio MCP colocated with its
  declared MCP SDK dependency, with one deterministic tool
  and a deliberate unhealthy mode.
- `scripts/qualify-managed-journey-provider.mjs` now launches App Server as an owned process group, captures PID,
  PPID, PGID, OS start marker and executable identity, reads resolved configuration, inspects actual MCP inventory,
  refuses all model turns and verifies that the complete process group has no survivors. Its launch composition now
  also accepts an explicitly bound alternate fixture command/environment for the P0.R2 exact-role probe without
  broadening the child's inherited environment.
- `scripts/tests/managed-journey-isolated-launch.test.mjs` covers composition, non-inheritance, receipt sanitization,
  deterministic modes, lexically normalized provider MCP maps and PID/PGID/OS-birth identity matching. Command remains
  recorded evidence but is allowed to change when the same process executes another image.

The only methods sent were `initialize`, `initialized`, `config/read`, `thread/start` and, when a thread existed,

was made to bypass that restriction.

## Acceptance boundary

P0.R0b qualifies launch isolation only. Every receipt deliberately remains `providerQualified: false`,
`mayStartTurn: false` with `native_tool_inventory_unavailable`: the upstream App Server did not supply trusted
post-filter model-visible native-tool evidence. The synthetic MCP is not native-manifest evidence and cannot close
`B0-001` or authorize a provider turn.
