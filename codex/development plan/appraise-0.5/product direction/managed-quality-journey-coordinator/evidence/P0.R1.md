# P0.R1 — Prototype the full-MCP and worker-gateway split

Status: `verified`

## Implemented proof artifact

- `src/lib/quality-journey/managed-worker-gateway.ts` derives six exact role profiles from the immutable v5 Factory
  definitions and canonical package MCP schemas. It recursively removes worker-selected principal fields and records
  trusted injection bindings without changing the remaining schema.
- A signed runtime grant binds target, Journey, work item, role, attempt, generation, lease, authorization, input,
  scope and exact profile digest. Pre-I/O authorization supplies the owner token only on the trusted side. The gateway
  re-verifies the grant and authorization after every attempted I/O and issues content-bound success, rejection or
  ambiguous-effect receipts.
- `packages/appraisejs/src/mcp/managed-worker-server.ts` exposes only a trusted profile whose digest matches the
  launch expectation, validates calls against the derived JSON Schema and delegates through the sealed grant. The
  existing full MCP stays behind a separate in-memory canonical ingress bridge using the existing server factory,
  coordinator client and specialized Journey handlers.
- The full `appraisejs` MCP factory and canonical registry were not narrowed or attached to a worker.

## Boundary

This is a disposable test-only gateway proof. It does not make the provider exact-tool capable, start a model turn,
cut over production dispatch or create new Journey lifecycle authority. P0.R2 must still establish trusted
post-filter provider evidence before any boundary probe or managed turn can use it.
