## Why the interaction changed

The earlier hosted control gave the human 15 seconds to read a return address, switch windows, paste it, and wait for a main-frame commit. The latest reviewed one-shot result records a human report of Protected checkout and a confirmation click, but no confirmed Scout admission and no retained close cause. It does not prove expiry caused the browser close. The user explicitly approved replacing manual paste with a human-authorized Appraise-executed exact return. An independent architecture review accepted the narrowed design after requiring proof of the exact `RETURNED` main-frame `GET` commit and preservation of separate pre-auth, return-approval and post-return human actions.

## Implemented boundary

The product Server Action accepts only the existing scoped session identity. After the human clicks **Authorize exact return**, the service derives the frozen target route, arms one 15-second one-shot grant, navigates the same owned page, and reports `RETURN_COMMITTED` only after the exact main-frame commit and provenance. The action projects the fixed outcome and sanitized session, dropping any unexpected return URL. No caller-supplied URL, credential, OTP, storage state, callback query or browser handle enters the operation. Failure before commit revokes the session; a late page-load failure after the committed exact return cannot rewrite that already-proven event. The human separately confirms protected access before receipt capture.

The public session projection withholds the current URL and provider origins throughout authenticated transit, including terminal failures. After the exact return commits, it reports only the frozen target route and origin. The internal policy retains its exact provider rules for containment.

The new qualification-only harness is isolated under `.appraisejs/c233-automated-return-20260927/`; earlier reviewed harnesses and failed-run bindings remain frozen. Its local control has six untimed human acknowledgements across two lineages: Checkout observation, combined MFA completion plus exact-return approval, and protected-access observation for each. It never displays a return URL. The owner IPC projects only a fixed committed outcome. Receipt capture, Scout admission, fresh-process old-scope rejection, authenticated second-session revocation checks, and teardown remain ordered in the driver. A fixed-enum first-failure stage/reason and latency bucket belong only to the sealed test result, never product receipts, Journey state or public projections. No live result has been generated with this harness.
