# P0.R2d — Canonical dynamic tools through a mandatory interlock

Status: blocked — canonical schema transport is lossy in Codex 0.154.0. The interlock refused all live requests;
this is a retained no-go, not a passing composition experiment.

## Authority and question

On 2026-09-11 the user accepted the proposed direction and requested an experiment plus plan/blocker updates:
"let's go with your direction. can you test it out and update plan accordingly with the blocker resolutions."
D14 adopts the temporary Appraise request/response boundary around D13 dynamic tools; D15 separates deterministic
development admission from production-provider admission. D10 remains the durable upstream target.

The experiment asks whether the canonical Requirement Analyzer tool profile can pass through a mandatory,
unchanged-byte request gate, return a permitted synthetic call through response enforcement, and reach the existing
sealed-grant worker gateway. Rejected requests must produce zero requests at the synthetic upstream. Rejected
responses must produce zero worker effect dispatches.

## Scope and evidence contract

This is an account-free local fixture, not a production adapter. Codex is network-confined to one gate listener;
the gate forwards only to a second fixed local listener. All replies and effects are synthetic. No real provider
credential or endpoint, database mutation, target browser or lifecycle transition belongs to this experiment.

Every accepted request must carry equal ingress/upstream-received byte lengths and SHA-256 hashes. Tool definitions
are derived from the canonical registry through the P0.R1 profile; body bytes must not be reconstructed from JSON.
The gate buffers a bounded complete synthetic SSE response and rejects unsupported content before release. This
narrow buffering strategy does not qualify the full production Responses event protocol.

D14 provenance means the canonical registry/profile/function/handler chain plus trusted gate/runtime binding and
outbound-byte evidence. It does not attest Codex-internal contributor origins or satisfy the upstream D10 checker.

## Exact live result

The final account-free run used Codex `0.154.0` and exited `2` with `qualified: false`. All three intended arms
stopped at request validation with exactly `tools_rejected`:

| Intended arm                     | Actual outcome                                                     | Synthetic upstream requests | Gateway effects | Cleanup                   |
| -------------------------------- | ------------------------------------------------------------------ | --------------------------- | --------------- | ------------------------- |
| Allowed canonical round trip     | Canonical schema rejected before forwarding                        | 0                           | 0               | Confirmed, zero survivors |
| Reversed-manifest request denial | Schema mismatch also prevented isolating the intended order denial | 0                           | 0               | Confirmed, zero survivors |
| Forbidden response denial        | Request never reached the synthetic response fixture               | 0                           | 0               | Confirmed, zero survivors |

Each arm's same-Seatbelt-profile TCP canary received an explicit permission denial when connecting to the second
listener. This proves that policy's forbidden-port denial with a separate Node probe, not a live Codex native-tool
escape probe. Codex itself was launched under that same profile. No real account/model request was reachable.

Both canonical tool names were present, with no extra tool:
`quality_journey_analysis_get` and `quality_journey_analysis_submit`. However, the submit schema lost **79 constraint
occurrences**: 26 `minLength`, 26 `maxLength`, 12 `pattern` and 15 `maxItems`. The gate preserves these in its expected
schema and refuses the actual reduced request. For example, `idempotencyKey` retains its string type on the wire
but loses its length and identifier-pattern restrictions.

The explicit pinned wire codec accounts only for root `$schema` metadata removal and `strict: false`. It does not
remove the 79 semantic constraints to obtain a pass. Full canonical local argument validation remains active and
rejects oversized or malformed identifiers; that effect protection does not restore the model-visible schema.

The [machine-readable receipt](P0.R2d.receipts.json) contains expected tool specifications, observed tool-only
specifications, per-arm source/executable/configuration identities, canary/cleanup results and the failed verdict.
Its canonical subject SHA-256 is `0137fb2d4bdec734562c2c220dbc249e71b10fd19892caa0124fd2bf9421c32b`.

## Direct tests and limits

53 focused tests pass. They cover canonical profile derivation, retained local canonical constraints, exact request
schema/order/header rejection before any forwarding callback, immutable byte copies, replay and authority snapshots,
complete-response consistency, malformed/unknown/incomplete SSE, bounded collection, callback identity and one-time
consumption, and rejection of unrelated failures as substitutes for the intended live denial conditions.

These are direct interlock tests. The allowed round trip, real response-denial path and byte equality at a live
upstream remain **unproved** because every actual request was rejected earlier. Fragment tests assemble bounded
chunks before validation; they do not qualify arbitrary production SSE streaming. The canonical effect handler is
synthetic and cannot change Journey lifecycle state.

## Diagnostic corrections

An initial diagnostic failed to save receipts because a URL pathname retained `%20`; source paths now use
`fileURLToPath`. A second timed out at initialization: a minimal sandboxed `--version` reproduction showed Seatbelt
requires `localhost:port`, not `127.0.0.1:port`, in its profile syntax. The corrected launcher also reuses the complete
R2c disabled-feature/configuration envelope. Both failures were harness defects, not evidence against provider
feasibility. The later schema-loss result is a separate provider behavior reproduced on the final artifact.

Independent review found and prompted repairs to vacuous response-negative tests, overly broad success conditions,
late buffer-limit enforcement and acceptance of calls omitted from completed output. The final tests require exact
rejection reasons and completion consistency. No diagnostic was relabeled as a passing provider result.
