## Current AppraiseJS source comparison

| Surface                | Existing reusable authority                                                                                                                                                                                     | Missing for the managed coordinator                                                                                                                                                                                                             |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Role/Factory contracts | Registry v5 defines six immutable roles, bounded tools/artifacts, capability profiles and required verified boundaries. `agent-factory.ts` canonicalizes spawn requests and validates adapter receipts/results. | No non-test call registers `AgentFactoryProviderAdapter`; production dispatch cannot currently select an adapter.                                                                                                                               |
| Work claim/dispatch    | `quality-journey-service.ts` atomically claims authorization, persists assignment/request/dispatch key, validates lease/owner tokens and records `DISPATCH_UNRESOLVED` rather than blindly retrying ambiguity.  | No Journey lease-renewal/heartbeat operation was found. Attempts do not persist runtime owner generation, process birth identity, provider thread/turn identity, stop state, attestation provenance, or outbox/inbox delivery state.            |
| Coordinator API/MCP    | Internal routes and MCP expose claim, dispatch, cancellation/revocation and specialized output ingress.                                                                                                         | The current external coordinator supplies lease/owner tokens, and cancel/revoke accepts a caller-selected actor. The managed runtime needs a narrower authenticated principal and cannot expose arbitrary actor/lifecycle selection to workers. |
| External handoff       | `quality-journey-handoff-service.ts` durably prepares/redeems a ticket and launches `codex app <workspace>` for local workspaces.                                                                               | This launches an external coordinator conversation; it does not supervise isolated role attempts and is the later cutover surface, not the managed adapter.                                                                                     |
| Test execution runtime | `quality-journey-runtime-service.ts` persists launch claims before starting prepared capsules and seals verified terminal bytes.                                                                                | `ProcessManager` ownership is in-memory and test-run-specific. It does not establish provider process recovery, singleton AI ownership or restart reconciliation.                                                                               |
| Public package/CLI     | `appraisejs` provides coordinator client, MCP stdio/HTTP, diagnostics and collaboration commands.                                                                                                               | No managed-runtime CLI/bootstrap/shutdown command or provider adapter registration exists. Root scripts likewise have no managed Journey runtime entrypoint.                                                                                    |
| Persistence            | Work items, immutable authorizations, attempts, assignment/request/receipt hashes and replacement lineage already exist.                                                                                        | No Start grant, runtime fencing owner, provider dispatch lifecycle, outbox/inbox, runtime attestation or browser-session grant records exist. These remain Phase 1 work after Gate G0.                                                          |

The comparison confirms the plan's baseline: AppraiseJS already owns durable Journey and specialized acceptance
authority, but operational scheduling/provider ownership is absent. This is not evidence that every past Journey
failure was caused by external coordination.

## Role-to-provider and broker candidate map

Every concrete operation below must be exposed through the attempt-scoped Appraise gateway. Codex native
filesystem, shell, general network, apps, skills, memory and lifecycle surfaces are not accepted substitutes.

| Role/profile                                 | Abstract tools                                                  | Required verified boundaries                            | Candidate mechanism to qualify                                                                                                                                                            |
| -------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Requirement Analyzer / `structured-analysis` | `artifact.read`, `artifact.propose`                             | `CONTEXT`, `LIFECYCLE_COMMAND`                          | Fresh configuration directory and thread; one required Appraise MCP; permission profile with no native effect tools; gateway resolves attempt and permits only analysis reads/proposals.  |
| Scout / `fast-observation`                   | `target.observe`, `evidence.publish`                            | `CONTEXT`, `TARGET`, `NETWORK`                          | Fresh thread plus an opaque browser-session grant; browser broker enforces target/origin/action scope and publishes evidence receipts; direct worker network/browser access disabled.     |
| Resource Explorer / `resource-resolution`    | `catalog.search`, `artifact.read`                               | `CONTEXT`, `TARGET`, `NETWORK`, `LIFECYCLE_COMMAND`     | Fresh thread and gateway-only catalog/read tools; no browser grant, target observation or direct network; explicit effective empty target/network scope where the assignment allows none. |
| Scenario Designer / `high-judgment-design`   | `artifact.read`, `scenario.propose`                             | `CONTEXT`, `LIFECYCLE_COMMAND`                          | Fresh thread and gateway-only approved discovery/analysis reads plus specialized scenario proposal ingress.                                                                               |
| Automator / `mechanical-implementation`      | `catalog.search`, `automation.write`, `runtime-capsule.publish` | `CONTEXT`, `FILESYSTEM`, `TARGET`, `LIFECYCLE_COMMAND`  | Fresh thread; brokered writes constrained to exact assignment paths/artifacts; permission profile/runtime workspace roots as defense in depth; no product-source or lifecycle mutation.   |
| Triager / `independent-attribution`          | `artifact.read`, `evidence.read`, `report.propose`              | `CONTEXT`, `FILESYSTEM`, `NETWORK`, `LIFECYCLE_COMMAND` | Fresh transcript-free thread; gateway-only sealed evidence/report operations; effective empty filesystem/network scope unless explicitly present; no target or automation mutation.       |

Candidate Codex controls include a dedicated configuration directory, `thread/start` with explicit instructions,
permissions, workspace roots, empty environment access and required MCP status verification before `turn/start`.
Generated-schema presence is only a hypothesis that these controls can support the contract. P0.2 must capture the
effective tool inventory and host evidence before accepting a `STARTED` receipt.

### P0.3 process/session-recovery fixtures

| ID      | Fault point                                                                    | Expected pass outcome                                                                                                                      |
| ------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `QR-01` | Supervisor dies before spawn.                                                  | Durable intent remains unstarted; exact effect may be retried only after proving no process was created.                                   |
| `QR-02` | Transport dies after process spawn but before process identity/`READY` commit. | Reconcile by executable plus OS birth identity, or remain `UNKNOWN`; never start a replacement while the process may exist.                |
| `QR-03` | Lose `thread/start` acknowledgement.                                           | Inspect the bound process/session and recover the exact thread, prove absence and retry, or remain unresolved.                             |
| `QR-04` | Lose `turn/start` acknowledgement.                                             | Inspect exact thread/turn state; no blind second turn.                                                                                     |
| `QR-05` | Resume the same attempt after restart.                                         | Resume only the persisted exact thread under a matching executable/config/runtime-capability digest; otherwise refuse same-attempt resume. |
| `QR-06` | Kill stdin/client while a turn or tool call is active.                         | Surviving process and effects are identified; late events are deduplicated and post-I/O authority is revalidated.                          |
| `QR-07` | Reuse a PID with a different birth identity.                                   | Stop/reconcile refuses to signal the unrelated process and reports actionable ownership loss.                                              |
| `QR-08` | Revoke during external I/O and deliver a late result.                          | New access stops immediately; occurred effects stay audited; late output cannot become accepted Journey state.                             |
| `QR-09` | Stop fails or descendants/background terminals survive.                        | Physical state remains `STOP_FAILED`/unresolved; no replacement starts until absence is proven.                                            |
| `QR-10` | Replay duplicate/out-of-order provider events after restart.                   | Stable delivery identity deduplicates identical events and rejects conflicting payload reuse.                                              |
