# C2.3.3 pre-contact target admission

## Outcome

The new browser-level gate prevents the popup initial-request escape in synthetic tests using both headed Chromium
and headless Chromium. This completes the bounded next containment experiment. It does not switch the production
browser backend, grant `EVERY_HOP`, or close C2.3.3/C-B04. The existing production adapter continues rejecting redirects.

Canonical test artifacts:

- `src/test/c233-target-transport.ts`: disposable Chromium ownership and flattened CDP over a private pipe.
- `src/test/c233-target-gate.ts`: exact seed binding, recursive target admission and native request gating.
- `src/services/coordinator/quality-journey-c233-target-gate.integration.test.ts`: real Chromium regressions.

The preceding page-bound prototype and its expected popup counterexample remain intact. The new tests prove the
repair mechanism separately; a green historical counterexample still means the old page-bound mechanism leaks.

## Implementation boundary

The harness obtains the executable and launch arguments from the installed Playwright `launchServer` for the selected
headed/headless mode, closes that discovery launcher, then creates a new owned process with a fresh temporary profile.
It preserves Playwright's static flags and uses `--remote-debugging-pipe`; no debugging TCP port is opened. It never
connects to the user's browser. On the tested macOS host, cleanup signals the owned process group and removes the
profile after browser exit and a check that the owned process group has no live descendants. A second signal is
used only if live descendants remain; defunct entries do not count as live. Windows process-tree cleanup is not
qualified by these tests.

Before creating the seed page, the browser connection creates a disposable context with `disposeOnDetach`, denies
downloads, and installs recursive-capable `Target.setAutoAttach` with `waitForDebuggerOnStart`. Attachments arriving
before `createTarget` returns stay paused until the returned ID binds the exact seed. Each admitted page receives
recursive auto-attach and request-stage Fetch interception before its final resume command. Unknown types, wrong or
missing context, duplicate identity, unsupported subtype, and unsupported opener lineage terminate the browser.
These rules follow the [Chromium Target protocol](https://chromedevtools.github.io/devtools-protocol/tot/Target/).

Production forbids popups. The default harness rule does too. One explicit test-only exception admits a direct popup
so the suite can prove that the popup's own Fetch gate is installed before its first request and that its nested popup
is denied. This exception is not a product policy change.

Allowed Fetch requests continue with only the original request ID, preserving native methods, body and cookies.
The gate selects URL, method, resource type and target identity; it does not log or inspect request headers or body.
The private CDP transport necessarily receives protocol data in memory. Only disposable loopback fixture servers
collect known synthetic cookie/body values for equality assertions. No human credentials, storage or IdP data is used.

## Evidence matrix

Seventeen checks run in each browser mode (34 tests total):

- Exact seed identity and guard-before-resume command ordering; runtime executable distinguishes headed/headless.
- Denied `window.open`, link and form popup destinations receive zero requests on a separate fixture server.
- An explicitly admitted direct test popup is guarded; its denied nested popup receives zero requests.
- A directly admitted test popup targeting a forbidden URL is denied by Fetch before the first HTTP request.
- 303 changes POST to GET; 307/308 preserve POST and identical synthetic bytes, with native cookie continuity.
- A denied redirect follow-up receives zero requests.
- Injected local failures before Fetch or recursive-attachment installation prevent page resume.
- A policy exception closes the browser before the paused target request is sent.
- Private-pipe loss stops the owned browser before a scheduled delayed request; the profile is removed.
- A real blob worker is rejected before its script can fetch, even though the request policy permits that destination.
- Explicit revocation while guard setup is paused prevents resume.
- Unexpected seed detach terminates the owned browser.

The tests exercise real Chromium network effects. Installation-failure injection throws locally before the named
command; it is not proof of every possible Chromium protocol-error response. Metadata rejection rules are implemented,
but malformed context/subtype/duplicate-input fault injection is not included in this slice.

## Rejected startup experiment

An early experiment launched full Chromium via `chromium.executablePath()` with a hand-built flag list. It exposed
an unrelated paused `other` target before the seed. Closing that target produced an acknowledgment without a timely
detach barrier. An initial popup pass did not prove the unknown target was destroyed before seed resume, and was
therefore not accepted as qualification. The final gate contains no quarantine/resume exception for unknown targets.

Using the executable and complete launch configuration actually selected by Playwright removes that startup blocker
in both tested modes. This does not establish which individual flag caused the difference, and the reduced flag
configuration remains unqualified. The final tests use strict rejection, not an exclusion filter or a detach that
might resume unsupported targets.

## Validation and next scope

The new suite passes 34 tests; the combined run with the existing CDP prototype and production Chromium containment
suite covers 56 tests, including the explicitly labeled historical popup counterexample. Affected ESLint, Prettier,
TypeScript and Fallow run without baseline changes. Canonical sources flow through scaffold preparation; Graphify
runs through the supported command. Independent review must bind the final exact artifact under `.appraisejs/`.
No new production build is required for these test-only helpers; the previous runtime repair build is historical.

The first independent rerun rejected the cleanup implementation: 7 headed cases failed because an unconditional
post-exit group SIGKILL returned macOS `EPERM`, also leaving one disposable profile and an unhandled rejection.
No owned Chromium processes remained. The repair checks live group members before a second signal, bounds exit waits,
and observes background cleanup rejections while preserving failures for awaited teardown. The identified orphan
profile was removed after the reviewer verified no owned browser remained. The repaired target suite passes 34 tests;
final acceptance requires re-review of the new artifact.

Next: implement and qualify the production adapter with canonical frozen-policy provenance, source/frame identity,
redirect lineage, authority epochs and receipt freshness. Preserve popup denial, service-worker and WebSocket
controls and prove their composition, subframe/OOPIF behavior, downloads and paused-request loss. A private-pipe
loss handled by a live owner is not an owner-crash or authenticated-restart qualification. Then obtain actual human
IdP/MFA, admitted Appraise receipt, authenticated restart and revocation evidence. C2.3.3 and parent C2.3 stay blocked;
C-B04 stays open; GC2 and C2.4–C2.7 are unchanged.
