# C2.3.3 production discovery adapter

This slice integrates the verified browser-level CDP target gate with the canonical discovery service. It does not
close C2.3.3, parent C2.3, or C-B04. Live human authentication/MFA, an admitted Appraise receipt from that session,
authenticated owner restart and revocation evidence remain required. GC2 remains `not_evaluated`; C2.4–C2.7 remain
pending and ineligible.

## Boundary and implementation

The production runtime owns a fresh Chromium process, temporary profile, disposable browser context, and private
debugging pipe. It derives the executable and launch flags from the installed Playwright version, then closes that
launcher before creating the owned browser. It does not attach to a user's browser or open a debugging TCP port.
Unsupported platforms fail closed. Credentials are entered only in the human-operated browser; public inputs do not gain
CDP, script, profile, cookie, or storage-state capabilities. CDP itself can transiently deliver request headers,
cookies and POST fields into the trusted Appraise process while decoding protocol events. The adapter synchronously
projects only required request identity and response status/Location metadata before asynchronous policy work; it does
not read, copy into service objects, log or persist credential fields. This is not browser-process-only secrecy.
Raw protocol tracing, process dumps and debugger inspection are outside the qualified no-retention boundary.

The adapter supplies the existing browser port. The discovery service still owns frozen policy provenance,
document-origin rules, authority epochs, explicit one-shot return, confirmation, receipt capture/admission, and all
lifecycle transitions. Request-stage Fetch interception invokes that policy before each network request. Its
`fetch({ maxRedirects: 0 })` port operation continues the original native request and waits at the response stage;
it does not replay requests or retrieve response bodies, and does not retain request bodies in service objects. Fulfillment continues the paused response only after the service's
response and epoch checks. Native redirect predecessor identity binds follow-up requests to their target and frame.

Exact seed admission and recursive guards precede target resume. Popups, workers, unknown targets, malformed scope,
duplicate identity and unsupported target subtypes are denied. Frame identity and committed URLs remain separate
from main-frame navigation authority. Child-frame success cannot satisfy authenticated return or confirmation.

Downloads are denied at the browser-context boundary. A deny-only WebSocket class is installed before document
execution in each admitted target. It captures only a fixed reporting binding, never the native socket constructor;
its frozen class/prototype and non-writable global cannot expose a native constructor. WebSocketStream is similarly
denied when present. Original response headers and bodies remain native and unchanged.
Service-worker registration suppression is defense in depth. Every initial worker-script request remains subject to
canonical network policy; an explicitly authorized script can be downloaded into Chromium before its worker target
exists. Worker targets are rejected while paused, before execution/effects. Appraise does not collect their bodies.
This is worker execution containment, not a claim that an authorized worker script is never fetched.

A provisional child's opaque/unknown origin does not inherit parent authority. Direct iframe-first IdP navigation
fails closed. A child first committed to the frozen target may subsequently cross origin under the selected policy;
its browser-reported security origin remains distinct from display URL and main-frame return authority. Headed
Chromium exercises an OOPIF, while the selected headless shell may keep that cross-origin child in the same process.

Transport or target loss fences the runtime before asynchronous cleanup, rejects outstanding operations, terminates
the owned process group and removes the profile. Synthetic pipe-loss evidence is not authenticated owner-crash or
restart evidence. The earlier Playwright, page-bound CDP, target-gate, and restart fixtures remain retained with their
original evidence limits.

## Qualification

The production integration suite exercises the actual canonical service and native adapter against disposable
loopback fixtures in headed and headless Chromium. Known synthetic form bytes and cookies are inspected only by
those fixture servers. No human credentials, storage, screenshots, page content, headers or bodies are retained in
production evidence. Synthetic persistence is explicitly not a live authenticated Scout admission.

Qualification covers native 301/302/303/307/308 redirect methods and cookie continuity; denied follow-up contact; explicit return and
receipt freshness; popup first-request denial; WebSocket/service-worker containment; same-process and OOPIF source
provenance; downloads; and outstanding-response revocation and pipe loss. Fault-injection checks cover malformed
target metadata, required response identity/status/header shape, and protocol/lineage failures. Exact command results and independent review are recorded with the
final artifact under `.appraisejs/c233-production-adapter/`.

Validation on 2026-09-19, macOS with installed Playwright 1.61.1:

- Canonical discovery policy/lifecycle, control, runtime fault and production integration suites: **209 passed**
  (91 existing policy/control cases, 39 protocol-fault cases, 79 native-browser cases).
- Retained target-gate, CDP prototype and historical Chromium qualification baseline: **56 passed**. Historical
  negative examples retain their original limits.
- TypeScript, affected-file ESLint and Prettier, production build, and Fallow commit gate: **passed**. Fallow reports
  zero introduced dead-code, complexity or duplication findings; no baseline or suppression changed.
- Canonical scaffold preparation and six-file source/test byte parity: **passed**. Graphify refreshed through the
  supported workflow. Linux is supported by the transport but is not qualified by this macOS run.

The initial 74-case production run had one headed classic-worker 5-second timeout; six focused reruns passed. The
worker case now has a scoped 15-second harness timeout, and the final 79-case native suite passes. The stronger
WebSocket fixture delays both binding and network observers, keeping handshake denial independent of prompt cleanup.
Fault tests additionally establish bounded seed admission, rejection on startup pipe loss, loader-correlated
DOMContentLoaded handling, and invalidation of missing child-frame origins. Transport pipe loss also removes the
owned profile before any service listener is registered.

Sandbox restrictions initially blocked loopback/Chromium, tsx IPC, temporary Git worktree creation and Google Fonts.
Authorized host retries passed; none of these restrictions prompted policy, baseline or source workarounds.

## Rejected containment experiments

A Proxy around the native WebSocket constructor exposed it through `prototype.constructor`. A delayed-observation
fixture showed a handshake reaching the server despite `Network.setBlockedURLs`; fast browser closure had hidden
that race. This is why final qualification delays observation and challenges recovered constructor paths and fresh
frames. The final boundary must be the pre-document deny-only replacement, not an observer racing network contact.

Adding CSP through either `Fetch.continueResponse` or response-stage `Fetch.fulfillRequest` produced the expected
network header but did not prevent a worker script request in the tested Chromium. These approaches are not retained
as controls. `Sec-Fetch-Dest` was absent at the tested Fetch pauses, so no header-based worker classifier is claimed.
An original server-supplied CSP still enforced its script restriction. No body-retrieval API was introduced.
