## Observations and repairs

The first human-operated attempt reached the provider login page and then closed before a receipt was issued.
An anonymous reproduction isolated a native font request failure: Fetch reported responseErrorReason Failed, and the
adapter closed under its existing fail-closed behavior. The HTTP HEAD probe returned 200 but does not explain the
browser-level failure. The exact lower-level font failure cause remains unproven.

The disposable provider policy now excludes the optional font. No origin/path authority was broadened, no browser
security setting changed, and production failure handling was not relaxed. The font is denied before network contact.

The first automated run completed login, explicit return, confirmation and receipt issuance. Real Scout admission
then rejected the harness placeholder snapshot hash because its repeated character was not hexadecimal. The harness
now hashes its bounded snapshot ID and receipt observation facts using the existing canonical hashing helper.

script or credential inputs. The separate operator control UI was not exercised by this automated run.
