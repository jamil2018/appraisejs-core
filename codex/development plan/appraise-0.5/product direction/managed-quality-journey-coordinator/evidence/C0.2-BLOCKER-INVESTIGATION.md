an adapter in the application server. Repeating claims consumes the immutable attempt allowance without
repairing this mismatch. Preserve the retained attempt-2 fixtures rather than use them for repeated probes.

Read-only callsite inspection found no production adapter registration in `src`, `packages/appraisejs/src` or
`packages/appraisejs/scripts`; registrations occur in tests. MCP claim/dispatch map to the same guarded services,
and CLI `mcp-call` only invokes the exposed tools. This is a source conclusion; out-of-repository runtime injection
was not inspected and is not claimed absent from every possible deployment.

## Dependency problem

The current register defers C-B02 to C2.1, which depends on GC1. GC1 follows C1, and C1 requires GC0.
However, GC0 itself requires one live graph task. Therefore deferring **all** admission work to C2.1 cannot
supply the missing GC0 evidence. C0.3 browser qualification remains necessary but cannot repair graph admission.

PLAN section 5 already permits a bounded follow-up experiment for a missing operation. Use that provision to
qualify an admission mechanism before GC0, while leaving production delivery and hardening in C2.1. Do not lower
GC0's evidence requirement or count the synthetic service adapter as a live stock-Codex result.

## Proposed C0.2e experiment — external assignment admission

This is a proposed, unexecuted experiment, not a new production API or an accepted contract change.

Use a disposable application checkout and newly migrated disposable database, with isolated fixture credentials
and explicitly selected test endpoint. Do not copy the retained hub database or its credentials. Preserve the
existing C0.1/C0.2 fixtures, historical registries and managed-worker path unchanged. Restrict the experiment to
Requirement Analyzer work and stop before discovery, scenario generation, execution or closure.

Prototype an explicit external-assignment admission mode at the authenticated service boundary. Bind it to the
transport principal, exact target/Journey/work item, immutable requirement/input revision, ownership generation,
lease and authorization attempt ceiling. Record a distinct external admission receipt, with no spawn claim and
no assertion of verified host context/tool isolation. A client-supplied task ID is correlation metadata, not
authentication. Shared coordinator credentials must not be presented as independently identified user principals.

Admission must atomically recheck eligibility, current ownership, input identity, authorization cancellation or
revocation, lease and human prerequisites. Keep the existing managed spawn-receipt checks intact. A separate,
explicitly versioned external contract must describe the weaker host assurance; do not reinterpret an issued
managed authorization or simply set an existing attempt to `IN_PROGRESS`. Reuse canonical Analysis artifact
validation, atomic persistence, publication and human-decision logic after valid external admission.

Prove the following against the isolated prototype before making a positive feasibility claim:

1. Through authenticated MCP, stock Codex claims/adopts one eligible external Analyzer assignment and submits a
   canonical valid candidate. Read back the immutable artifact and its exact assignment/input lineage.
2. Reject schema-invalid and semantically invalid candidates without writes. Use otherwise-valid payloads for
   wrong-principal, wrong-target, stale-generation, expired/revoked authority and changed-input probes so that
   schema errors cannot mask the intended enforcement check.
3. Race two admissions; demonstrate exactly one active assignment. Use a second Journey to prove isolation of
   target, lease, idempotency and accepted artifact scope.
4. Suppress an acknowledgement only after the server commits. Reconnect and read durable outcome before retry;
   exact replay returns the same artifact, and changed payload under the same key conflicts without a second write.
5. Stop the host task, resume from a fresh task, reconcile before takeover and show the replaced owner cannot
   commit. Do not claim that Appraise cancels arbitrary stock-Codex work on the host.
6. Publish through the canonical path and show a required unresolved question/human decision blocks advancement.
   Stop before granting that decision or entering the next lifecycle stage.

Record source/diff hashes, contract version, test endpoint identity, fixture IDs, host version, sanitized live
trace and cleanup disposition. Service tests are prerequisites; only the real MCP cycle supplies live evidence.
Independent C0.4 review must evaluate the external assurance contract and C0.3 evidence before any GC0 verdict.
If admission cannot be made honest under that contract, retain a negative result rather than manufacture receipts.

## Alternatives ruled out

- A no-op adapter returning `STARTED` for the current task would misrepresent spawn and runtime confinement.
- Allowing `WORKER_REQUESTED` submissions or directly editing status bypasses admission instead of qualifying it.
- Generic work completion, worker registration, skills and handoff redemption do not supply the missing trusted
  admission transition. A different client transport does not change the service requirement.
- Reviving the archived managed-runtime experiments would test a different architecture and is not the default
  escape from this stock-Codex qualification gap.
