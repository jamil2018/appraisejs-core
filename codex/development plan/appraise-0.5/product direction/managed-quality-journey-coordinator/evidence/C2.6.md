# C2.6 — Consent-bound execution and reconciliation

Status: `verified` after independent exact-artifact review. GC2 remains `not_evaluated`; C2.7 is not started.

## Scope and authority

The existing Journey execution reservation, `RuntimeCapsuleTestRunService` attempt, process launch, and runtime reconciliation remain the only managed execution path. No independent TestRun, generic Journey command, or MCP caller can manufacture UI consent or a Journey evidence receipt. The root source is canonical; matching files were synchronized into `create-appraisejs` with `prepare-template`.

## Change and expected outcome

- Consent scope now includes a canonical hash of Journey/cycle/state, target and fingerprint, Environment ID and snapshot, browser, complete frozen prepared-capsule content, and rerun lineage. A changed input cannot consume an old grant. The actual consumed UI consent ID is recorded in `START_EXECUTION` even when Appraise auto-selects it.
- The local Journey UI can revoke an exact requested or granted unused consent. Repeated revocation is idempotent. Consumption and reservation occur transactionally; after consumption, stopping execution requires cancellation. There is no MCP consent mutation.
- A lost launch reply reuses the existing durable cycle and TestRun. `LAUNCHING` is an uncertain claim, not permission to respawn. A changed request under the same idempotency key conflicts.
- Evidence reconciliation requires the exact Journey-intent TestRun and run identity, frozen prepared membership, matching environment, capsule/attempt relationship, manifest lineage, and managed artifact bytes. It rejects an independent TestRun before sealing. New command receipts name `reports/traces` and `reports/screenshots`, the Cucumber runtime's actual output subtrees. Persisted v1 receipts with legacy `traces` and `screenshots` roots still parse and retain their exact paths. Journey receipts hash retained trace and report-step screenshot bytes, including the screenshot's test case and report-step identity.
