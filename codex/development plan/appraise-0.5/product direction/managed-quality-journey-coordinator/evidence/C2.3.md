## Implemented boundary

C2.3 adds a headed, non-persistent Appraise browser broker bound to the exact Journey, target project, active
Discovery revision, Scout work item, environment and frozen route. Its action and service inputs deliberately have no
credential, cookie, storage-state, arbitrary URL or JavaScript field. Contexts reject downloads, service workers,
websockets, popups, cross-Journey bindings, stale Discovery revisions and requests outside the selected environment's
exact origin and frozen routes. Request interception is installed at browser-context scope before page creation, and
an idle timer closes browser resources at expiry without waiting for another Appraise operation. Sessions remain
in-memory, so a server restart invalidates their process-instance binding.

Anonymous sessions can capture directly. Authenticated-intent sessions require the human to enter credentials, SSO
challenges and MFA only in the headed browser and then separately confirm that the scoped page is accessible. That
confirmation records local access only; it neither identifies a natural person nor attests an identity-provider
claim. Missing access creates a durable Appraise blocker with a bounded reason and a fresh-session recovery command.
Expiry, logout, revocation and context replacement have distinct terminal states.

Receipt capture derives facts from the current sanitized target URL and access outcome rather than
accepting observation prose from a browser host or client. The immutable artifact is sealed with a canonical SHA-256
content hash and declares issuer `APPRAISE_DISCOVERY_BROWSER_V1` and strength `APPRAISE_OWNED_BROWSER`. Scout
submission reuses C2.1's transaction-local specialized admission and requires the exact artifact descriptor,
Journey, target, cycle, Discovery revision, work item, snapshot, environment, route and receipt-derived fact.
Target-controlled page-title content and free-form missing-access text are never persisted. Unknown, supplemental,
stale, conflicting, missing-access or tampered receipts are rejected before persistence.

The Journey UI exposes only the active frozen Discovery scope and keeps browser availability, human-confirmed access,
receipt capture and Scout submission distinct. Root source was propagated through the supported scaffold preparation
workflow; no generated automation wrapper or second lifecycle engine was added.

The C2.3.3 implementation adds a versioned, canonical `Environment` authentication-transit policy. Authenticated
sessions select one frozen flow and bind its policy hash, Environment scope version and flow ID. Each main-frame
transition is authorized by exact document origin, destination origin, canonical path, method and request kind;
redirects are fetched with zero automatic hops and checked with HTTP redirect-method semantics. IdP origins remain
broker-internal transit authority and never enter Scout `networkOrigins`. Final confirmation and capture still require
an explicitly authorized return to the exact selected target origin and frozen route. WebSockets, popups, downloads,
service workers, stale policies and non-main-frame attempts remain denied. Authenticated receipts add only the frozen
scope version, flow ID, policy hash and `RETURNED_TO_FROZEN_TARGET` outcome; they do not contain IdP URLs, redirect
parameters, bodies, cookies, tokens, account identifiers or page content.

## Live browser observation

The repository's bundled Browser harness was not exposed in this Codex session, so no substitute browser was used.
An opt-in qualification harness instead launched the real default Appraise Playwright runtime in headed mode against
a disposable loopback Checkout target and an exact HTTPS test-provider flow. The operator reported completing the
provider login and local body-discarding second-factor form with all values entered only in that browser. No
screenshot, trace, request body, credential, cookie, target content or provider content was captured or persisted.

The isolated Appraise browser process had terminated when the harness checked for the returned session. The harness
therefore could not confirm access, capture an Appraise-issued sealed receipt, submit through the real Scout boundary,
or proceed to its separate-process restart and fresh-session revocation checks. The report of human interaction is a
live host observation only and is not promoted to Appraise evidence. The sanitized result directory contains no
result artifact. Two earlier attempts also produced no evidence: one stopped before launch on non-canonical fixture
policy JSON, and one timed out without human operation after the desktop-control bridge returned too late.

Deterministic coverage now includes exact cross-origin transit policy canonicalization and freezing, per-hop
origin/path/method/request-kind enforcement, redirect semantics, target-only Scout authority, authenticated receipt
binding, atomic freshness/admission, restart loss, replacement, expiry, logout, revocation and secret-canary
containment. It does not replace the missing admitted live receipt.
