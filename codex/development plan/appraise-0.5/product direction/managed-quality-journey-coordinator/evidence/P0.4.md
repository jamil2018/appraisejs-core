# P0.4 — Review feasibility and browser enforcement

- Status: `in_review`
- Source identity: branch `codex/managed-quality-journey-coordinator-p0`; initial independent review was bound to
  commit `5cc6bc756d58c4251bddee8d6119c1a8a7d227c0`; corrected proof identity pending re-review.
- Changed surfaces: controlled browser-boundary prototype and tests, Phase 0 evidence/register integration and
  validation documentation.
- Acceptance evidence:
  - Browser prototype uses a fresh in-memory context, blocks service workers, intercepts every HTTP request,
    inspects redirects before the browser follows them, closes WebSockets without connecting to their server,
    denies downloads/unapproved exact URLs and exposes a worker view without session setup or generic evaluation.
  - `QBR-01` proved allowed same-origin redirects and blocked a disallowed redirect before the disallowed loopback
    server was reached. The first implementation allowed the redirect hop to reach that server; the regression test
    caught it and the prototype was changed to fetch without following redirects, inspect `Location`, then fulfill
    only an allowed response.
  - `QBR-02` independently checks denied frame/background URLs, blocked service workers, a WebSocket that never
    reaches the disallowed server and an allowed download response cancelled by the browser event path.
  - `QBR-03` is narrower than its predeclared full fixture: it shows a synthetic HttpOnly session exists only in its
    live context, is absent after context replacement and is configured only through the trusted controller view.
    It does not prove human login, SSO/MFA or service/browser-process restart.
  - `QBR-04` proves only that hostile text is returned as observation data through a worker view without generic
    evaluation. It does not include a model, real gateway capability or cross-Journey secret and therefore does not
    establish prompt-injection containment.
  - `QBR-05` now sends an allowed GET, denies POST before network I/O, rejects a query-altered GET and confirms the
    mutation fixture received no request. GET is allowed only by exact URL, not assumed globally side-effect-free.
  - The prototype establishes a useful controlled routing/context mechanism. It does not fully qualify the planned
    human-authenticated browser boundary, Codex worker isolation or production authority.
