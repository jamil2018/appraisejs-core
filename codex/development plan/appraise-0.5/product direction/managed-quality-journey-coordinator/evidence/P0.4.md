# P0.4 — Review feasibility and browser enforcement

- Status: `in_review`
- Source identity: branch `codex/managed-quality-journey-coordinator-p0`; exact working-tree patch digest and
  independent review identity pending final validation.
- Changed surfaces: controlled browser-boundary prototype and tests, Phase 0 evidence/register integration and
  validation documentation.
- Acceptance evidence:
  - Browser prototype uses a fresh in-memory context, blocks service workers, intercepts every HTTP request,
    inspects redirects before the browser follows them, closes WebSockets without connecting to their server,
    denies downloads/unapproved paths and exposes observation methods rather than a generic evaluation API.
  - `QBR-01` proved allowed same-origin redirects and blocked a disallowed redirect before the disallowed loopback
    server was reached. The first implementation allowed the redirect hop to reach that server; the regression test
    caught it and the prototype was changed to fetch without following redirects, inspect `Location`, then fulfill
    only an allowed response.
  - `QBR-02` covered frames, background fetch, service workers, WebSockets and a download route. `QBR-03` showed a
    synthetic HttpOnly session is available only in its live context and absent after context replacement.
    `QBR-04` treated malicious instruction-like page text only as returned observation data. `QBR-05` denied POST
    while allowing an explicitly scoped GET.
  - This prototype establishes a viable first-release browser enforcement path for the controlled channels. It does
    not qualify Codex worker isolation or turn the prototype into production authority.
