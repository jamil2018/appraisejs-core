# P0.R2a — Stress-test a mandatory Responses wire-gateway candidate

Status: `verified` — candidate feasibility only; P0.R2 remains blocked

## Question and disposition

Could AppraiseJS avoid maintaining a Codex fork by placing a mandatory local request/response interlock between the
stock Codex App Server and its model provider?

The experiment verified a narrower candidate architecture:

- Codex `0.153.4` can resolve a custom Responses provider at one loopback listener, disable WebSockets, and set the
  documented request and stream retry budgets to zero.
- macOS Seatbelt can confine the complete App Server process tree to that exact listener port while denying an
  alternate live loopback port and external DNS/network access.
- The interlock can observe and hash the exact serialized request bytes, inspect the complete ordered wire-tool
  objects, receive only a synthetic bearer canary, and return synthetic Responses streams accepted by this Codex
  build.
- A synthetic allowed MCP function call was dispatched and its result appeared as `function_call_output` in the next
  locally captured request.

The passive validation-and-forwarding theory was falsified. Even with one synthetic MCP tool, `dynamicTools: []`, an
isolated home/configuration and no ambient MCP server, the actual request contained ten top-level tool entries. They
included shell/session tools, MCP resource enumeration, user input, image inspection, multi-agent, the intended MCP
namespace and web search. A role-exact validator would therefore reject the stock request.

A compatibility bridge must instead be a security-critical request/response interlock that constructs or transforms
the final outbound request, attests the exact post-transformation bytes, forwards only those immutable bytes, buffers
tool-bearing response events, and releases only schema-valid calls bound to the P0.R1 role profile and handler. A
logging proxy or `base_url` setting is not sufficient.

This verifies local feasibility, not production qualification. No request was forwarded, no external model or DNS
endpoint was reachable, no real account state or credential was used, and no billing-capable provider call occurred.
`B0-001`, P0.R2 and Gate G0 remain blocked.

incomplete security-critical code.

## Disposable harness and reviewable receipts

The account-free runner and listener remained under `/private/tmp` and were removed from the product artifact. The
reviewable [receipt set](P0.R2a.receipts.json) records:

- exact executable, configuration and Seatbelt-profile hashes;
- the complete ordered tool names, types and per-definition hashes;
- the six failure-mode request counts, byte counts and raw-body hashes;
- the two-second observation duration and per-run sandbox wrapper PID, PPID, PGID and birth marker;
- authorization presence/scheme only;
- the synthetic function-call event and the second request's ordered input item types; and
- confinement controls, cleanup result and explicit limitations.

The existing P0.R0a qualification suite supplies the committed negative coverage for missing, extra, duplicate,
reordered, origin- and schema-mutated manifests. P0.R2a adds observed wire definitions and does not claim a production
gateway implementation. This avoids retaining a bespoke partial schema validator or syntactic receipt verifier that
could later be mistaken for the qualified boundary.

## Architecture consequence

The candidate can avoid a maintained Codex fork only by moving final model-request and streamed tool-call authority
into AppraiseJS. The production interlock would become part of the trusted computing base and must:

1. make itself the sole reachable model egress for the owned Codex process tree;
2. build or transform the complete outbound request into the exact role surface before attestation;
3. bind and forward the exact accepted bytes without a later parse/reserialize step;
4. keep provider credentials, prompts and raw responses out of logs and durable receipts;
5. buffer every tool-bearing response event until name, namespace, schema, origin, handler and attempt binding pass;
6. reject alternate paths, retries, replays, unknown event forms and configuration drift; and
7. requalify every Codex, protocol, role profile, gateway or confinement-policy change.

The upstream two-phase prepare-and-bound-dispatch contract remains the selected durable solution. This wire interlock
is a verified compatibility candidate, not an adopted replacement. Adopting it requires explicit acceptance of the
Appraise-owned security and maintenance boundary plus separately authorized provider-native authentication/model-I/O
qualification.

## Remaining proof before P0.R2 can pass through this route

- Decide whether the candidate is an authorized temporary bridge or only retained research.
- Implement production request construction/transformation and prove its post-transform exact-byte binding.
- Implement streaming response interception across every tool-bearing event form and prove zero forbidden dispatches.
- Qualify provider-native account authentication without credential persistence or leakage.
- Prove the gateway can forward only to one fixed upstream while Codex remains confined to the gateway.
- Execute retry, auth recovery, stale/replayed receipt and cleanup tests against that production path.
- Re-run all six P0.R3 roles and the P0.R4 recovery matrix against one exact artifact.

## Independent review

An independent judge accepted snapshot
`c873f8f1783d6d19fb7adb8790c29baaa4dd3cbd60827ca4c119cfa288d6df03` strictly for candidate feasibility. The
review confirmed the receipt hash and exact Codex identity, tool manifest, failure-window request counts, synthetic
MCP round trip, confinement controls and cleanup. It also retained every limitation above: the disposable runner is
not reproducible production evidence, two-second windows do not prove permanent absence of replay, the sandbox
wrapper is not provider-issued attestation, and production forwarding/authentication/transformation/stream filtering,
all-role qualification and recovery remain unverified. The requested judge role and bounded context were not
host-attested; no static harness claim substitutes for that missing runtime proof.
