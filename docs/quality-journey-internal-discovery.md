# Internal Discovery delivery (M08)

On supported Chromium captures the receipt can also record the presence of visible email inputs, password inputs, submit controls and headings. These fixed categories carry no element text, selectors or field values. Appraise checks the original scoped document during capture. Older receipts retain the facts originally collected.

Managed Journey continuation starts Scout and Resource Explorer through these same scoped submissions. Discovery status changes refresh the activity panel even when the lifecycle hash does not change. Their server opt-in is `APPRAISE_LOCAL_CODEX_DISCOVERY_ENABLED=true`. See the [operator guide](quality-journey-operator-guide.md).

Before claiming Scout or Resource Explorer work, Appraise checks the local worker executable. The managed JSONL sender supports the pinned macOS Codex 0.169.1 build and the signed 0.171.0-alpha.13 build. If an earlier attempt stopped at this executable check, Appraise can verify that no worker started and no submission was accepted, then create a fresh Discovery revision using the existing approved criteria. An unknown outcome after worker launch still requires reconciliation.

An explicitly selected `APP_SERVER_LOCAL_V1` Journey can admit Scout and Resource Explorer to an in-process,
attempt-scoped gateway for disposable verification. Appraise's exact Analysis approval creates the Discovery revision and
both assignments. The trusted coordinator uses the existing versioned claim and admission services with its current
durable session. The gateway binds its signed grant to the project, Journey, role, attempt, assignment generation,
lease, input hash, scope hash, and worker tool profile. The grant expires with the lease.

- **Scout** reads the approved charter, frozen target routes and environment IDs, and Appraise-issued browser evidence
  for the active revision. Use the receipt's snapshot ID, capture time and content hash in the Target Observation Bundle.
  Each fact must appear in a referenced receipt. The gateway grants no browser, network, credential or capture tool.
- **Resource Explorer** reads the approved charter and frozen resource inventory through the same role-scoped Discovery
  read. Resolve candidates by stable ID and cite the exact Appraise-issued Analysis or approval artifact from the
  assignment. General catalog search and browser receipts are outside this worker profile.

The Resource Explorer read also returns supplemental `resourceLabels` for exact frozen candidates. Project-owned
active locators and modules may expose their display names only after the current row matches its frozen hash and
project. Ready steps may expose their canonical human expression only after exact ID/version/content equality and
current visibility or verified built-in source equality. Labels are bounded plain text; selectors, definition source,
credential values and unrelated catalog entries are not projected. Labels neither alter stored frozen scope/hashes
nor authorize another candidate. Stale, archived, foreign and unverifiable candidates remain unlabeled.

For one exact frozen environment and route with no sign-in policy, managed continuation opens an anonymous,
nonpersistent Appraise browser, captures read-only control-presence evidence, and closes it before Scout starts.
A deterministic internal browser ownership identity reserves this operation before native launch; concurrent wakes,
restart, failures, or UNKNOWN cleanup cannot replay it automatically. Capture declines pages with a visible password
input, and runtimes without the bounded control-presence observation, before persisting any receipt. Configured auth
policies, ambiguous environment/route selections, and declined anonymous attempts remain in the Discovery panel.
Its sign-in and exact-return confirmation are human decisions. Scout waits before claim while no admissible receipt exists. When the human marks missing access, the active Discovery blocker parks both
roles. That wait consumes no new attempt and creates no qualifying evidence. Protected capture still requires the
existing authorized sign-in flow, one-shot return, and human confirmation in the scoped browser.

The specialized Discovery services recheck the current revision, frozen registry and exact assignment in their write
transactions. Scout submissions reject raw browser evidence. Both roles reject changed Environment bindings and expired
grants. Appraise records acceptance and completes the Discovery revision when both bundles qualify. Any later lifecycle
transition still goes through Appraise's existing command boundary.

The in-process gateway and its cross-package fixture are repository-only. The staged E2 mixed-invalidation fence remains
in effect. The fixture uses fresh migrated SQLite, in-memory worker MCP, and a deterministic browser adapter. It covers
anonymous capture, both specialized acceptances, protected-access denial and parking, and stale inputs. No real protected
sign-in occurred. Runtime and provider qualification remain unverified. The historical M06 STOP and spent attempts retain
their original status.
