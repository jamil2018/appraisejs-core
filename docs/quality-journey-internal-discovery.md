# Internal Discovery delivery (M08)

An explicitly selected `APP_SERVER_LOCAL_V1` Journey can admit Scout and Resource Explorer to an in-process,
attempt-scoped gateway for disposable verification. Appraise's exact Analysis approval creates the Discovery revision and
both assignments. The trusted coordinator uses the existing versioned claim and admission services with its current
durable session. The gateway binds its signed grant to the project, Journey, role, attempt, assignment generation,
lease, input hash, scope hash, and worker tool profile. The grant expires with the lease.

- **Scout** reads the approved charter, frozen target routes and environment IDs, and Appraise-issued browser evidence
  for the active revision. Use the receipt's snapshot ID, capture time and content hash in the Target Observation Bundle.
  Each fact must appear in a referenced receipt. The gateway grants no browser, network, credential or capture tool.
- **Resource Explorer** reads the approved charter and frozen resource inventory through the same role-scoped Discovery
  read. Resolve candidates by stable ID and cite the exact Appraise-issued Analysis or approval artifact from the
  assignment. General catalog search and browser receipts are outside this worker profile.

The human uses the existing Discovery browser panel for anonymous capture and protected sign-in. Scout waits before
claim while no admissible receipt exists. When the human marks missing access, the active Discovery blocker parks both
roles. That wait consumes no new attempt and creates no qualifying evidence. Protected capture still requires the
existing authorized sign-in flow, one-shot return, and human confirmation in the scoped browser.

The specialized Discovery services recheck the current revision, frozen registry and exact assignment in their write
transactions. Scout submissions reject raw browser evidence. Both roles reject changed Environment bindings and expired
grants. Appraise records acceptance and completes the Discovery revision when both bundles qualify. Any later lifecycle
transition still goes through Appraise's existing command boundary.

The in-process gateway and its cross-package fixture are repository-only. The staged E2 mixed-invalidation fence remains
in effect. The fixture uses fresh migrated SQLite, in-memory worker MCP, and a deterministic browser adapter. It covers
anonymous capture, both specialized acceptances, protected-access denial and parking, and stale inputs. No real protected
sign-in occurred. Runtime and provider qualification remain unverified. The historical M06 STOP and spent attempts retain
their original status.
