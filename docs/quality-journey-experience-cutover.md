# Quality Journey Authority Cutover

Appraise home opens the Quality Journey brief. On desktop, the Chats pane groups recent Journeys and active drafts
by project. Use its search and sort controls or open **All Journeys** for the full project library. **New chat** opens
the same brief. Workspace contains the metrics Dashboard at `/dashboard` and the manual authoring and execution tools.
The mobile menu links to the brief and the full Journey library. Quality Journey is the sole agent-enabled quality workflow.

Choose **New chat** or **New journey**, enter a brief, and choose **Start journey**. The project-scoped draft autosaves. Starting freezes the saved version and submits the requirement once. Structured details from older drafts remain part of the requirement. New journeys use the local managed agent.

The Journey screen groups lifecycle stages into **Requirements → Scenarios → Test run → Results**. One activity line reports the current work, pending decision, or interruption. Only the current stage presents actions. **History** holds the original brief, prior requirements and answers, the event timeline and the evidence library.

The analyzer inspects static page labels from the registered environment before drafting criteria. It uses the original brief, saved answers and prior feedback to ask essential questions. Review criteria before scenarios. Request a change on a specific criterion to receive a successor revision and compare the wording. An explicit review or execution permission applies to its exact version and scope.

Eligible managed tasks continue after server-side decisions and when a user reconnects. Worker availability depends on configured role support. Legacy journeys keep their records and use the in-app ownership reconciliation flow. **Pause** records the user request and preserves progress. See the [operator guide](quality-journey-operator-guide.md).

The unreleased Quality Plan and Assessment experiences were deleted without redirects, compatibility pages, data
conversion, exporters, or deprecated aliases. Historical development plans remain archival documents only and are
not current product contracts.

Existing development databases that applied the removed August 2026 migration chain must be reset. The consolidated
Journey migration supports fresh databases and rehearsal from the last retained July schema; it intentionally does
not preserve removed-domain rows.

Independent Test Runs remain in the Execution area as non-authoritative diagnostics. Their reports and logs help
debug authored automation, but only sealed Journey evidence and Journey review/closure records establish quality
outcomes.
