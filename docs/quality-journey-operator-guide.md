# Quality Journey operator guide

This guide covers the supported stock-Codex, Appraise-owned Journey path. Open the selected Journey in Appraise and use its current stage, blockers, handoff, and operational controls as the source of truth. A Codex message, deep-link launch, setup screen, or independent Test Run does not advance a Journey. [Lifecycle flow](agent-lifecycle-flow.md), [MCP setup](agent-mcp-setup.md), and [compatibility](quality-journey-compatibility.md) give the detailed contracts.

## Connect and observe

1. Confirm the Journey's immutable requirement and selected target. From **Agent setup**, install the package-shipped skills-only plugin or use the documented manual MCP registration. Run `appraisejs agent compatibility --json`, reconnect the task, and call `project_diagnostic` against the actual target. A saved diagnostic is historical; inspect current capabilities, contract hash, hub, and target before work.
2. Use **Prepare and open Codex** on the Journey. For a local target, the validated workspace is opened. A remote target uses a neutral host directory while its normalized URL remains the target identity. If Codex or its URI handler is unavailable, copy the bounded prompt and send it manually in a suitable task. The link only prefills a composer; the user must send it. Do not put credentials, full requirements, or approval receipts in the prompt.
3. Redeem the one-time ticket against the exact Journey and target, then read `quality_journey_get` and the relevant stage state. An expired, replayed, superseded, or mismatched ticket needs a fresh handoff. A launch request or open composer is not a connection; redemption is connection evidence, not work authorization.

The Journey page's **Last checked** time is the last successful status observation, not Codex's last activity or proof of liveness. Visible pages poll about every ten seconds, back off on read failure, and stop after closure; a failed read leaves the last known snapshot marked potentially outdated. Use **Check for updates** and explicitly **Load newer version** before making an exact-version decision. Handoff `connectedAt`, assignment lease and generation, durable events, and pending blockers have separate meanings. Silence, an absent heartbeat, and a previously connected task do not establish success or failure. Treat external Codex status as unknown unless separately observed.

For a later-stage return, inspect the existing handoff and authoritative Journey. Stock Codex has no qualified known-task reopen contract here; prepare a fresh scoped handoff if the recorded task is missing, archived, or unavailable. The local Journey UI issues a short-lived, request-bound takeover approval only after an exact reread and reconciliation. Takeover fences the predecessor generation; redemption alone cannot approve it. Ambiguous dispatch, uncertain execution, and expired leases block automatic replacement. A reconnect or fresh task never renews an assignment, reuses an approval, or replays a launch.

## Work through the lifecycle

| Stage or interruption             | Operator action and evidence boundary                                                                                                                                                                                                                                 |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Requirement analysis              | Keep the confirmed requirement revision fixed. Review the submitted analysis or answer bounded questions in Appraise; retain exact question and answer lineage.                                                                                                       |
| Discovery                         | Start anonymous. Use the qualified Appraise-owned browser session for human login, SSO, or MFA when required; never send credentials to the agent. Missing access is a visible blocker, and supplemental human observations do not replace required trusted evidence. |
| Scenario design and revision      | Review the exact candidate portfolio in Appraise. A rejection or changed content requires a new bound review; old approval does not cover a new artifact.                                                                                                             |
| Automation preparation            | Use approved scenario revisions and canonical operations within the current assignment. Inspect prepared artifacts and verification before execution; do not treat preparation as consent or product-code repair authority.                                           |
| Execution                         | Grant exact Appraise execution consent when requested. Track reservation, launch, TestRun, capsule, logs, and sealed evidence by cycle identity. An uncertain `LAUNCHING` outcome requires reconciliation, never a fresh launch merely because a reply was lost.      |
| Triage, remediation, and rerun    | Read the sealed failed-run evidence, review the proposed correction and required decisions, then issue fresh scoped work or consent as the Journey requests. Preserve lineage to the failed run and changed artifact.                                                 |
| Report and closure                | Review the report and any allowed risk acceptance in Appraise. Close through the dedicated Journey control only after its required decisions and evidence are complete; an agent's final message does not close it.                                                   |
| Human wait or task outage         | Keep the durable blocker visible. On crash, offline, or quota interruption, reread committed outcomes and leases before a fresh claim. There is no automatic model, billing, or background-wake fallback.                                                             |
| Target edit, deletion, or archive | Expect a mismatch, rebind, new revision, or refusal as appropriate. Historical evidence remains; do not silently carry prior authority to a different target.                                                                                                         |

## Pause, cancellation, and manual recovery

Use the local Journey **Pause journey** control with a reason when admissions must stop. Pause fences new work and snapshots owned cleanup targets while preserving accepted decisions and sealed evidence. The UI reports owned browser and execution cleanup separately; external Codex task status remains unknown. Resume only after the Journey's existing reconciliation succeeds. A sealed result may wait for resume before lifecycle publication, and an earlier admitted spawn may still need cleanup. See [pause and recovery](quality-journey-recovery.md).

An execution cycle in `CANCELLING` is still nonterminal. Terminal cancellation requires durable output completion joined with a hash-bound live-supervisor stop receipt and canonical browser-close acknowledgement. A lost reply can be recovered from the same cycle and receipt. If process inspection is denied, private ownership is lost, browser closure is unknown, or a launch remains ambiguous, keep the Journey paused and the effect unresolved. Inspect the recorded cycle, browser ownership, and cleanup observations; use the supported Appraise recovery path after establishing actual resource state. Escalate unresolved host resources for manual investigation. Never signal a persisted PID/PGID, infer cleanup from an empty process-local map, reset the database, fabricate an approval, or retry an uncertain external effect. Three earlier disposable lost-ownership fixtures remain unresolved; complete host cleanup has not been shown.

For manual recovery, keep the Journey paused, retain a database backup and collect the exact Journey, generation,
assignment, cycle/TestRun, owned-browser row and existing stop/output receipt identities. Record observations without
credentials, callback URLs or browser profile contents. If the original owning hub/supervisor is still available with
its private live handle, retry the supported cleanup and reread the same durable outcome before resume. If that
ownership is lost, this version provides no forced reattachment or manual terminalization command: preserve the
unknown records and escalate the bounded identities and sanitized observations for investigation. Merely closing a
window or restarting the machine does not manufacture the canonical receipt. Access rotation, a fresh handoff and a
matching application upgrade do not resolve uncertain effects or permit duplicate execution.

## Upgrade, disconnect, and restore access

Back up the SQLite database before a known migration, then run the matching application upgrade with `npm run migrate-db`. The supported startup scripts gate installation inventory and storage compatibility before readiness writes. Missing migration SQL/directories, changed SQL or a missing inventory refuse access; restore matching application files rather than authoring an inventory to hide damage. Future or unknown migration history, checksum changes, unfinished/duplicate/gapped records, and populated databases without history refuse startup or upgrade without repair or reset. Use the matching newer application and diagnose the refusal; do not bypass the guard with bare Prisma, direct Next, or ledger edits. An older arbitrary binary is outside the supported refusal guarantee. The integrity reference does not prove a full physical-schema audit or signed supply-chain authenticity.

`appraisejs agent disconnect --cwd <hub> --json` revokes the hub credential while retaining Journey data. `appraisejs agent plugin uninstall --cwd <hub> --json` revokes first, then removes guidance; a removal failure does not restore access. Raw `codex plugin remove` removes guidance only. Already admitted work and owned execution still require pause and reconciliation. For intentional restoration, run `appraisejs agent reconnect --cwd <hub> --json`, reconfigure the MCP transport with `agent setup --json`, start a fresh task or reconnect the transport, and run `project_diagnostic` plus authoritative Journey reads. Old credentials remain rejected, and access restoration does not transfer assignments or decisions.

The observed host version, package guidance version, and client matrix are in [compatibility](quality-journey-compatibility.md). Other or unreported Codex versions and absent task schema observations require diagnostics. Earlier C1–C3.2 qualifications are scoped evidence, not fresh-install verification. C3.3 onboarding and clean-install qualification, and GC3 release evaluation, remain separate; this guide does not claim either has passed.
