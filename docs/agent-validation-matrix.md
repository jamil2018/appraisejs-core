# Agent Validation Matrix

Use the narrowest check that can catch likely regressions, then broaden when the touched surface is shared, packaged,
or release-like.

| Touched area                             | Focused checks                                                                                                                                                                                                                                                     | Broader checks                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------ |
| Agent docs, skills, routing, PR template | `npm run check:harness`; `npx prettier --check --ignore-unknown AGENTS.md docs/agent-*.md .agents/skills/appraise-*/SKILL.md .cursor/rules/project-context.mdc packages/*/AGENTS.md .github/PULL_REQUEST_TEMPLATE.md scripts/check-agent-harness.mjs package.json` | `npm run lint` only if code blocks or config changes warrant it                |
| CRUD/domain service/action               | affected unit tests; `npx eslint <files>`; `npx prettier --check <files>`                                                                                                                                                                                          | `npm run validate:unit`; `npm run build` for shared contracts                  |
| Prisma schema or migrations              | migration validation; affected service tests                                                                                                                                                                                                                       | `npm run build`; scaffold template preparation if generated apps are affected  |
| Automation sync                          | dry-run sync when available; affected sync tests                                                                                                                                                                                                                   | `npm run sync-all`; `npm run build` for shared parser/generator changes        |
| Test execution, reports, logs            | focused unit tests; targeted Cucumber or Playwright checks                                                                                                                                                                                                         | `npm run validate`; `npm run build` for runtime/config changes                 |
| React route/component                    | affected tests; file-level ESLint and Prettier                                                                                                                                                                                                                     | Playwright smoke for user-facing flows; `npm run build` for route-wide changes |
| Scaffold/package `create-appraisejs`     | `npm --prefix packages/create-appraisejs run prepare-template`; package tests                                                                                                                                                                                      | package build for release-like changes                                         |
| CLI/MCP package `appraisejs`             | `npm --prefix packages/appraisejs run test`; `npm run setup:mcp` for setup docs                                                                                                                                                                                    | `npm run build:appraisejs`; MCP E2E for tool/transport changes                 |
| CI, package config, build config         | config formatter or parser checks                                                                                                                                                                                                                                  | `npm run build`; relevant package tests                                        |

Run Fallow and React Doctor through `npm run quality:fallow:commit` and `npm run quality:react-doctor:commit` before
publishing when the changed surface could affect commit hooks or code quality gates.
