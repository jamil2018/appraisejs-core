## Bootstrap gate before E0

Full native descriptors may only appear after a turn constructs a provider request. N0's zero-turn
records cannot establish otherwise. E0 would be a descriptor-only capture, not mapping execution,
B07 testing or isolation qualification. It must not emit a generic executor call or use a second
model loop to drive the worker.

Before requesting E0 authority, require:

1. An exact reviewed boundary/composition artifact and a supported enforcement mechanism whose
   relevant effective properties have evidence. No configuration-only controls suffice.
2. A separately approved implementation slice for new transport/enforcement/collector adapters,
   deterministic negative tests and independent exact-artifact review. Accepted B1 bytes stay frozen.
3. If effective boundary evidence requires running hostile synthetic fixtures, a separate bounded
   enforcement-qualification authorization **before E0**, with its own processes/paths/effects and
   budgets. N2 authorizes no such probes, even if they use no Codex or model.
4. Complete startup gating: ownership/pins/config/environment/FDs; required scoped MCP catalog;
   storage acknowledgement; exact provider endpoint; automatic auth/ambient discovery disabled
   and independently controlled. Broad descriptor exposure must not imply callable execution.

This is a real bootstrap blocker, not a reason to waive containment. The enforcement proof need
not depend on an already captured native manifest: it must independently constrain the worker's
effective filesystem/process/network privileges, including unknown exposed capabilities. If that
cannot be established, E0 stays ineligible. Native/provider credential isolation remains outside
synthetic evidence; no real credentials are introduced merely to qualify collection.

N2 should evaluate the smallest sufficient capture with the following proposed ceiling. Do not

| Additional helpers/guests                        | Zero unless exact mechanism requires a separately enumerated and approved process set                                                    |

| Deadlines                                        | 60 seconds for acknowledgement/capture; 180 seconds overall                                                                              |

These are **new proposed E0 counters**, not M01's exhausted 3/3 allocation and not P1's
15-thread/14-turn/55-request matrix. A scripted capture turn is still a runtime start requiring
explicit new authority; “no inference” does not mean “no effect” or “no start.”
Before launch, record durable intent for each process and listener attempt; before each start,
reserve the exact slot. Failed or ambiguous attempts consume their slot and fence the whole run.
No retry, restart, resume, replacement or reallocation. Unknown acknowledgement is never resent.

Proposed E0 behavior: inspect at most the first request, project only descriptor-bearing containers
and required correlations, then end capture without a model/tool response. The exact artifact must
specify how its non-success terminal provider response or owned-channel closure causes a bounded
stop, and test that behavior offline. Do not improvise an HTTP/SSE response at runtime. Native turn
failure/UNKNOWN may be retained even if descriptor bytes were captured; clean completion is not
required to claim capture, and capture is not accepted Journey work.

Preserve original descriptor/container semantics and order; hash exact inspected bytes plus the
projected descriptor structure. Do not persist raw prompts, transcript/provider bodies or secret
values. Bound per-request bytes at 1 MiB, descriptor evidence at 1 MiB and sanitized metadata at
64 KiB. If exact schemas exceed bounds or sanitization changes semantics, stop with incomplete
capture; never truncate and call it a complete map. Any actual second request, auth header, redirect,
network escape, permission request, effect or loss of ownership fences the run. Exposed descriptor
names alone may be retained as negative evidence; no exposed capability is invoked.
