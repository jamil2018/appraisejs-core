# M13 C1 original native outcome contract

Status: design candidate; enrollment closed pending bounded source closure and independent review. This is not an
execution packet, an inference allocation, or a physical qualification receipt.

C0 observes native readiness, role delivery, fencing and cleanup while leaving provider termination unproven and the
HUB occupied. C1 adds an original-owner source for one ordinary completed turn without changing production dispatch
refusals, D05, unavailable native defaults, schema, migrations, or synthetic SQLite NONSTART custody.

original armed send permit to that owner before initialize. After the one consuming turn, fence and seal the actual
sender and consumed permit with exact correlated thread/turn identity and final issued-request/written-byte range.

uncertainty remains disqualifying even after an in-flight counter returns to zero. All actual writes, heartbeats,
responses, native streams, process group and SDK cleanup must settle without ambiguity.

The original task parent first holds an unqualified candidate. Once native/SDK cleanup completes, it may remain alive
with all effect gates closed during one separately frozen finite independent-review interval. It emits a sanitized,
immutable candidate digest. At most one task-control decision binds that candidate, reviewed source dossier, exact

review acceptance cannot manufacture observations. Only then may it privately enroll a task-scoped physical source.
No caller-supplied qualification flag, general enrollment setter or arbitrary proof constructor is allowed.

pending operation, failed cleanup, changed identity or unresolved commit preserves UNKNOWN and leaves the HUB occupied.

## Accepted database-domain correction

The solver and independent custody review select a C1-only original-client factory with private unpredictable
per-connection TEMP markers installed before resolver query-only mode. This identifies continuing SQLite connections;
a copy of the main database carries no TEMP marker. The source owner's unpredictable SourceState incarnation and
matching CREATED ledger provide the persistent enrollment marker. No caller-supplied domain-proof flag is accepted.

Before native acquisition, with exclusive factory admission and no active source holds/lookups/interactive transaction,
verify both TEMP markers and the persistent marker, then run the finite lock-domain probe: canonical raw BEGIN
EXCLUSIVE/ROLLBACK succeeds; the original query-only resolver begins and reads the persistent marker, holding SHARED;
canonical BEGIN EXCLUSIVE must return the exact installed-engine representation of SQLite BUSY primary code 5; the
resolver commits; canonical BEGIN EXCLUSIVE/ROLLBACK succeeds after release. Recheck markers, settings and pathname
identity. Arbitrary rejection, SQLITE_LOCKED, timeout or message-regex matching cannot substitute for BUSY.

Retain every original Promise and transaction state, including original cleanup after unexpected success. Unsupported
or ambiguous behavior refuses proof. This is a cooperative connection-domain proof, without an OS-held-FD or hostile
filesystem claim. Do not repeat the probe during ambiguous commit or replay. Canonical native transactions check the
captured TEMP marker after the first-statement SourceState CAS and before business writes; original positive resolver
reads check their own TEMP marker. Never recreate a lost marker on an admitted source. Rotation or changed identity
preserves UNKNOWN. Existing synthetic factory behavior remains unchanged; no persistent schema or dependency change
is authorized by this correction.

## Accepted identity sequencing

The connection-domain probe remains before native acquisition. Initial SourceState and CREATED identity bindings retain
null thread/turn handles and never change. Existing SQL makes identityJson immutable; C1 does not alter that trigger,
its schema, or lifecycle constraints. After IDs are observed from the same original transport, one source-owned
`RECEIPT_RESERVED` record with strict native payload version `M13_NATIVE_IDENTITY_BOUND_V1` records their unique binding.
This uses an existing ledger kind. Insert and seq/head/byte-count CAS are atomic while ACTIVE with no pending operation.

Native proof/replay validation joins initial immutable SourceState/CREATED, this unique tagged binding, final physical
receipt and original sender identity. It cannot directly compare the initial null-handle identityJson with the final
receipt, accept a second binding, or let a caller supply substitute IDs. This is original observation binding, with no
source reincarnation or reconstruction. Superseded sequencing proposals remain rejected evidence.
