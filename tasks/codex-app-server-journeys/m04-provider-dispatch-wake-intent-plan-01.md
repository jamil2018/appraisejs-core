## Required invariants and proposed persistence

Names are proposed; preserve these invariants even if implementation chooses fewer tables.

1. **One logical run per attempt.** New `QualityJourneyProviderRun` has a unique non-null `attemptId`, stable run ID, Journey/target/role, immutable session and coordinator generation, assignment ID/generation, authorization/admission IDs and hashes, lease ID, frozen input/scope/revision hashes, provider kind and versioned configuration digest. Validate relational scope against the immutable M03 binding, not caller-provided copies alone. An attempt never acquires a second logical run to recover a timeout. Legacy attempts may have zero provider rows. A run may have multiple explicitly numbered turn intents under the frozen three-turn cap; M04 first establishes the initial turn only, without adding a correction loop.
2. **Operational correlation is immutable and non-authoritative.** Store thread/turn handles only when trusted evidence supplies them; never fill missing handles from intent IDs. Namespace native handles by provider state/installation identity and applicable server incarnation. Unique thread ownership prevents cross-attempt context reuse; unique native turn claims prevent two logical runs from adopting one native turn. Repeated identical acknowledgements replay; changed correlation conflicts and fences. Session generation, assignment generation, dispatch claim epoch and future transport generation remain distinct.
3. **Durable dispatch intent.** Proposed `QualityJourneyProviderDispatchIntent`, unique `(providerRunId, turnOrdinal)` and scoped idempotency key/request digest. Persist operation intent and exact sanitized envelope/config digest before any external action. Track claim owner/epoch, claim expiry, send-boundary identity/time, acknowledged handles/evidence, uncertainty and reconciliation independently. Reusing a key with changed payload is a conflict. Raw credentials, prompts, transcripts and provider account payloads do not belong in these rows.
4. **Hub-wide exclusion.** Proposed singleton `QualityJourneyProviderSlot` scoped to this canonical hub database, capacity one. CAS and unique ownership serialize all Journeys, roles and supervisors, including different targets. A separate database is a separate hub; do not imply distributed exclusion across copied databases. Possibly-sent, active, stopping or uncertain effects retain the slot until reconciled. A claim lease expiring is not permission to recycle the physical turn slot.
5. **Wake outbox.** Proposed `QualityJourneyWakeIntent`, scoped to canonical hub/Journey/target and a stable cause identity (event ID or exact operation receipt/revision), with unique cause key, bounded reason, sequence/high-water reference, claim epoch/expiry and processing acknowledgement. No bearer, assignment secret, prompt or native process handle in a wake. Delivery may repeat; processing means canonical state was reread, never that work was approved or dispatched. Keep outbox delivery state separate from immutable Journey events.
6. **Budgets and deadlines.** Persist a versioned operating policy snapshot and actual reservations. Frozen D05: one active turn per hub; lease 120 seconds, heartbeat 40 seconds; acknowledgement maximum 60 seconds; turn maximum 15 minutes from durable send boundary; at most three turns per attempt; at most three attempts or lower canonical remaining ceiling; human waits consume zero turns. Unknown send consumes a turn reservation conservatively. Exact replay cannot debit twice. Confirmed non-start records evidence and retains reservation history; no new logical run or automatic fourth attempt. Persist earliest history-creating intent and retention deadlines (24 hours after reconciled terminal outcome; unresolved seven-day escalation), never reset clocks on restart. M05 owns timers, transport renewal/interruption and actual cleanup; M04 supplies enforceable persistence and deterministic eligibility checks, without claiming live timing or spend enforcement.
7. **Assignment secret continuity.** External claim needs a caller-held secret and stable request identity before claiming. Persist an internal preclaim correlation/request digest and reference to protected supervisor credential storage before claim, or make claim plus internal dispatch preparation one canonical transaction. Never store plaintext secret in outbox/run metadata or rely on process memory to recover it. Choose the smallest transaction-local composition first; later secure credential provisioning remains separate from model-visible data and provider authentication. A crash cannot cause a fresh claim to replace an orphaned attempt.

Lost commit acknowledgement at every boundary requires an authoritative DB reread by the original operation key and digest. Read exact committed receipt; if absent on the authoritative database and the transaction is known rolled back, retry that same operation identity. If the database cannot establish outcome, stop. In particular, discovering a committed send marker after a lost arm reply does **not** recreate the one-use send permit. Treat it as possibly sent and require reconciliation. This trades availability for safety.

A pending intent with no send boundary can be reclaimed under a new claim epoch after expiry only with fresh authority checks. Once armed, missing send observation, timeout, missing native handle, process exit or lease expiry never proves non-start. Restart after arming, whether before or after the actual send, is UNKNOWN unless authoritative evidence identifies the original run or proves non-start. No blind resend or automatic replacement. An old paused sender must be unable to invoke the sink after an authoritative slot release; model this explicitly in offline checks, with actual transport enforcement deferred to M05 qualification. Any later explicitly eligible retry is an additional audited operation under the same logical run, preserves the earlier evidence, rechecks all fences and budgets, and cannot be enabled merely by a timeout label.

Pause/cancel/revoke fences new eligibility first and records a wake/reconciliation need in the canonical transaction. Before arming, pending work can become invalidated without external effects. After arming, retain uncertainty and slot ownership until authoritative reconciliation. Transfer remains trusted-human, quiescent and transactional; new run/intent records must join that quiescence check even if the attempt is terminal. Revision changes invalidate unsent intent; an already armed intent retains old immutable correlation and cannot write into the new revision. Historical authenticated outcomes remain readable.

## Decisions and handoff

The plan recommends conservative one-run-per-attempt correlation, separate turn intents, database-wide hub exclusion and durable polling discovery. It accepts conservative UNKNOWN after an armed-but-unobserved crash, including a crash before the actual send. These are proposed implementation choices for review, not new provider authority. Names/index details can be resolved during implementation without changing the invariants.

Before implementation, the user must authorize this bounded plan. The credential continuity boundary is explicit: no production secret store is selected by this proposal; preserve the exact synthetic secret for offline checks, and keep live claim-to-dispatch integration blocked until a protected recoverable credential reference is designed and approved within its own scope. No new model/auth/budget/process-lifetime choice is needed for the SQLite-only slice. M05 must separately decide per-turn child plus resume versus persistent child, protected supervisor credential lifecycle and effective transport/containment qualification. If later requirements demand automatic resend or release of uncertain slot ownership, return for a contract decision rather than weakening M00.
