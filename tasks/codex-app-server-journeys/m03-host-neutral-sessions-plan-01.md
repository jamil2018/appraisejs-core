## Proposed ownership model (names provisional; invariants required)

1. Persist Journey hosting selection independently of WorkAttempt admission. Proposed values: `EXTERNAL_LEGACY` for retained external/Factory behavior, `APP_SERVER_LOCAL_V1` for explicit internal managed hosting, `LEGACY_UNRESOLVED` for migration quarantine. The last is a recovery classification, not an execution fallback. New ordinary Journeys explicitly persist the compatibility value at creation; internal opt-in explicitly persists app-server hosting. Provider availability, login, errors, restart or missing executable never choose or change the value.
2. Add a host-neutral session row (`QualityJourneyCoordinatorSession`, proposed): scoped Journey/target, stable session ID, monotonic coordinator generation, authenticated owner/principal reference, host kind, status, predecessor, optional legacy handoff reference, exact activation/transfer request identity and result, timestamps and fencing/recovery reason. Keep raw credentials, prompts, account payloads and provider history out. Native thread handles are operational metadata only; no native handle is needed in the first path.
3. Persist one current session reference and ownership version per Journey. Use a unique `(journeyId, targetProjectId, generation)` session key and a transactional CAS on the Journey ownership version/current pointer. A session is valid only if its target matches the Journey, it is the selected current session, its generation matches, its status permits the requested operation and it is unfenced. Target matching needs service checks as well as appropriate relational constraints; a standalone session-ID foreign key is insufficient.
4. Persist attempt-to-session association for every new `APP_SERVER_LOCAL_V1` attempt at claim in the same transaction. Proven legacy handoff paths map their compatibility session. An explicitly persisted no-session legacy compatibility path retains only its bounded historical authority and records that provenance without inventing a session or managed ownership; missing mode or unresolved ownership is not this exception. Proposed side table (`QualityJourneyWorkAttemptSessionBinding`) records immutable attempt, session, coordinator generation, assignment generation and provenance. Session/generation may be absent only on an explicitly classified legacy provenance record, never for app-server-hosted work. Use a side table for provable legacy associations too, without rewriting legacy manifests, receipts, owner-token hashes or request/result hashes. No association may be inferred merely from an attempt admission label or creation-time proximity.
5. Keep coordinator generation, assignment generation and any future transport generation separate. Both session identity and attempt association must agree with the current principal, target/Journey, role, work/attempt, authorization, lease, input/scope and idempotency identity for new managed effects. Never accept an arbitrary session-ID string as authentication.
6. Keep legacy handoffs readable and compatibility credentials resolvable through a verified handoff-to-session association. Preserve effective historical acceptance/refusal semantics. Do not require fake desktop tickets for app-server sessions and do not reinterpret provider task IDs as authority.
7. Registration is non-authoritative. For an explicitly selected, quiescent internal managed Journey with no predecessor, an authenticated initial-session activation consumes an explicit scoped activation request, CASes the null pointer/version and commits generation 1. It starts no work. This is the narrow bootstrap exception to requiring an already-current session to create the first session, not an exception for takeover, claim, admission or worker writes. If prior ownership/effects exist, refuse bootstrap and enter recovery/transfer. Every subsequent managed takeover requires the current predecessor session plus an exact approved transfer request and registered successor; absence of credentials cannot become a takeover.
8. Human decisions retain existing trusted UI/auth boundaries. Omitted worker credentials must fail on managed Journeys; distinguish a verified human decision path from an omitted optional object. Pause/cancel/reconciliation paths may remain available under their existing human/recovery authority but cannot create new work or revive a fenced session.

## Migration and backfill rules

Add a new append-only migration and update `prisma/migration-inventory.json`; do not edit predecessor migrations. Inspect the compatibility runner (`scripts/migrate-compatible.mjs` and its helpers), SQLite SQL and inventory contracts before implementing. Migration must work on both an empty DB and supported upgraded DBs; SQL default alone is not an ownership classifier.

- Inventory each Journey's target, effective handoffs (takeover/connected/fenced state), live and terminal attempts, Factory/external principals and assignment/lease/dispatch lineage. Perform deterministic classification without contacting a provider. Use only stable database fields, with recorded reason/provenance for unresolved cases; avoid wall-clock-dependent ownership inference.
- A unique effective legacy takeover with consistent target and non-conflicting ownership can receive a provenance-bound compatibility session reproducing its existing effective generation/fence semantics. Do not pick a newer merely PREPARED/CONNECTED ticket instead of the effective takeover. Preserve already-fenced history and reserve generation allocation above all historical session/handoff generations.
- An unambiguous known legacy owner remains on its existing behavior, whether its attempts are `MANAGED`, `EXTERNAL_V1`, or both across reconciled history. Mixed historical admission labels alone do not prove mixed current owners. Preserve owner tokens, assignment generations and active leases byte-for-byte. No upgrade automatically transfers active managed work.
- Where no authoritative owner can be proved, or live ownership conflicts across principals/targets/handoffs/attempts, classify `LEGACY_UNRESOLVED`, leave current authority unset and expose a recovery reason. Never fabricate a current session/principal from labels or timestamp ordering. Retain read access and separately authorized recovery, block new managed effects.
- An empty legacy Journey without ownership/effects may retain explicitly bounded preexisting compatibility behavior; it receives no app-server session. This compatibility branch must be selected by persisted mode/provenance, not by absence of a session alone. Missing-mode/corrupt values fail closed.
- Existing attempts keep their exact admission value and immutable payloads. Add legacy session associations only where lineage proves them; otherwise retain an unresolved association/provenance and block adoption into managed hosting. Preserve all terminal acceptance receipts and UNKNOWN/dispatch-unresolved records. Do not rehash historical idempotency requests or reset counters.
- Pure SQL should create schema and deterministic backfill when possible. If classification needs TypeScript validation, use a versioned idempotent transactional classifier, with a persisted pending/quarantine state until it finishes. Do not permit normal writes between structural migration and classification. Choose the mechanism after inspecting actual supported SQLite migration constraints; never silently run a non-atomic upgrade on a live DB.
- A second application/restart must not mint new owners/generations or alter the classification result. Migration interruption is rollback or explicit pending recovery, never automatic activation. Validate foreign keys, unique current ownership, row counts and selected historical byte/hash equality.

## Transaction boundaries and failure behavior

| Operation              | Required atomic boundary and outcome                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Create/select mode     | Persist explicit hosting choice with Journey creation; normalize omitted compatibility input without changing historical replay hashes. Same key/different explicit mode conflicts. Draft confirmation remains one transaction. No mode selection dispatches work.                                                                                                                                                                                                                                                                                                      |
| Initial activation     | Read target/mode/principal and absence of prior ownership/effects; acquire ownership CAS; insert session/generation and activation receipt; set current pointer in one SQLite transaction. Losing concurrent activation rolls back fully. Exact retry returns the recorded result with currentness reported separately.                                                                                                                                                                                                                                                 |
| Takeover/transfer      | Check current predecessor session and expected ownership version; consume exact trusted human approval bound to target, mode, snapshot and successor; re-read active/unknown effects; fence predecessor, reconcile or invalidate authorized old work, persist successor and pointer and result together. No partial cancellation/fencing on failure. Unknown dispatch/tool/cleanup or mixed ownership refuses transfer.                                                                                                                                                 |
| Claim/admit            | Recheck current mode/session/owner and ownership CAS in the transaction that checks authorization/budget/WorkItem version, creates claim/attempt binding, or admits the assignment. For `APP_SERVER_LOCAL_V1`, no new claim or admission with missing/stale/foreign session, including before first takeover. Proven handoff compatibility uses its mapped session; explicitly classified no-session legacy work retains its preexisting bounded authority and provenance only. Unresolved ownership refuses new work.                                                  |
| Six specialized writes | Enforce the hosting-mode-specific fence in the transaction that accepts the canonical artifact and durable acceptance row: mandatory current session for app-server hosting, proven mapped session for legacy handoff authority, and only explicitly classified bounded historical behavior for no-session legacy work. Gateway prechecks alone do not qualify this. Takeover and worker writes contend on the same ownership CAS/write fence; either the old write commits first and changes the approval snapshot, or takeover commits first and the old write fails. |
| Retry/outcome lookup   | Authenticated exact historical outcome lookup remains possible without granting present mutation authority. Existing replay paths may return a receipt, but must never activate, renew, allocate or relabel it current. Missing/stale worker sessions cannot turn a replay into a new effect.                                                                                                                                                                                                                                                                           |
| SQLite contention      | Keep transactions short; no process/network/provider I/O inside. Unique/CAS failure rolls back and returns conflict/recovery guidance. Busy/stale transaction errors are not permission to resend a claim/transfer; re-read and reconcile the exact operation identity first. Verify using two independent Prisma clients on one SQLite file.                                                                                                                                                                                                                           |
| Availability/restart   | Session/attempt history survives restart. An unavailable provider parks existing mode; it does not activate another host. No stored PID kill, auto-claim, lease renewal, effect retry or inferred cleanup.                                                                                                                                                                                                                                                                                                                                                              |

Cross-host transfer is explicit and quiescent/reconciled. Existing desktop takeover's `ACTIVE_EFFECTS_FENCEABLE` cancellation logic is useful source, but does not prove that an app-server process/effect stopped. Active managed work requires an explicit transfer decision, confirmed reconciliation/quiescence and preserved attempt budgets. If that evidence is unavailable in M03, refuse transfer; do not build M04/M05 supervision to unblock it. Existing compatibility takeover semantics remain isolated and tested.
