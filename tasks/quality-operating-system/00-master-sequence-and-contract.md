# Quality Operating System: Master Sequence And Contract

## Goal

Turn AppraiseJS into an active quality operating system while retaining the host agent as the semantic reasoning
engine. Appraise supplies versioned methods, strict artifacts, deterministic critique, immutable approvals, managed
execution, attributed findings, and exact decisions.

## Authority chain

```text
User source
→ requirement analysis proposal
→ query resolution and exact analysis approval
→ validation strategy and scenario proposal
→ exact design approval
→ mechanical realization and preflight
→ execution preview and consent
→ managed execution
→ sealed observations and attributed findings
→ outcome review and exact quality decision
```

## Non-negotiable invariants

- Facts, agent inferences, assumptions, queries, observations, attributions, and target outcomes remain distinct.
- No obligation exists without an exact approved analysis origin.
- No validation is realized or published without an exact approved design.
- Every execution is governed by the target consent mode and immutable execution manifest.
- A failed TestRun is an observation, never a target verdict.
- Only reviewed `TARGET_DEFECT` findings may support a target-negative decision.
- Built-in methodology versions remain resolvable for every persisted reference.
- Public third-party methodology installation is deferred.

## Delivery order

Implement slices 01–08 in order. Schema and public-contract decisions are sequential; bounded tests, UI, and docs may
proceed concurrently only after the relevant contract is committed. Each slice must leave the repository buildable
and receive focused deterministic validation before the next slice begins.
